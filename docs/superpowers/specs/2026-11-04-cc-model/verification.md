## 1. 集成面声明与双向映射

| 集成面 | 说明 | 覆盖场景 |
|--------|------|---------|
| I-1 settings.json 替换语义（外部接口） | ANTHROPIC_* 全量替换、非前缀键与其他顶层内容保留、失败不变性 | S1、S2、S10 |
| I-2 切换链路组装（store+writer+detector+菜单） | 点菜单 → 替换 → 记录 → 通知 → 重排 | S1、S2、S11、S15 |

## 2. 场景清单

自动化场景（S9、S10）以单元测试承载，其余为人工清单——集成链涉及 NSStatusItem/NSMenu/系统授权，人工核对并明确标注，不伪装自动化。

### S1 切换主路径【人工】
- 前置：备份真实 `~/.claude/settings.json` 至临时目录；应用已运行且至少两个模型（智谱、DeepSeek），当前为智谱。
- 步骤：点状态项 → 菜单点「DeepSeek」。
- 期望：

| # | 期望 | 出处 |
|---|------|------|
| 1 | env 中全部 ANTHROPIC_* 键组与 DeepSeek 模型保存值完全一致 | §2 F2 |
| 2 | `DISABLE_AUTOUPDATER` 等非前缀键、`enabledPlugins` 等顶层字段原值保留 | §2 F2 |
| 3 | 系统通知文案逐字「已切换到 DeepSeek，对新建会话生效」 | §2 F2 |
| 4 | 重开菜单：DeepSeek 置顶带勾选；智谱不在首位 | §2 F1 |
| 5 | 状态项标题变为「⇄ DeepSeek」 | §2 F1 |
- 清理：恢复备份的 settings.json。
- 内容等价核对：切换前后文件用 JSON 语义比对（键序/缩进变化可接受）。

### S2 切换失败不变性【人工】
- 前置：S1 备份就绪；将 settings.json 内容改为非法 JSON。
- 步骤：点菜单任意模型。
- 期望：失败通知逐字「切换到〈name〉失败，已保留原配置」；settings.json 字节不变；存储中 lastSelectedAt 未变。出处：§2 F2 出口表。
- 清理：恢复备份。

### S3 自定义配置·纳入新模型【人工】
- 前置：S1 备份就绪；settings.json 的 env 改成任何模型都不匹配的值。
- 步骤：开菜单 → 关闭菜单。
- 期望：菜单顶部置灰「自定义配置」逐字；菜单关闭后弹窗；输入已有模型的重名 → 提示改名不关闭；输入新名「Test」→ 列表 +1、Test 成为当前（置顶勾选）、收到切换通知。出处：§2 F3（2026-11-05 裁决含三出口）。
- 追加核对（Task 5 审查裁定，2026-11-05）：未命中态打开菜单 → 点击任一模型项 → 菜单关闭后**不弹**纳入弹窗（该项已切换为当前、env 已命中）。
- 清理：恢复备份；移除 Test 模型（或整目录还原）。

### S4 自定义配置·覆盖已有模型【人工】
- 前置：S3 前置就绪。
- 步骤：弹窗选「覆盖已有模型」→ 下拉选「智谱」→ 确认。
- 期望：智谱的 env 键组被当前 env 整体替换（键集合也换）；显示名「智谱」与默认标记不变；智谱成为当前。出处：§2 F3（2026-11-05 裁决）。
- 清理：恢复备份。

### S5 取消后不再重复弹窗【人工】
- 前置：S3 前置就绪。
- 步骤：弹窗点「取消」→ 再次开/关菜单 → 手动改 env 中任一键值 → 再开/关菜单。
- 期望：取消后同 env 不再弹窗，置灰项保留；env 变化后再次弹窗。出处：§2 F3。
- 清理：恢复备份。

### S6 首跑全流程【人工】
- 前置：临时应用配置目录（无模型；已裁决，2026-11-05：应用支持环境变量 `CC_MODEL_CONFIG_DIR` 覆盖配置目录，无 UI、文档记录）；真实 settings.json 保持智谱配置；备份就绪。
- 步骤：启动应用 → 欢迎窗「开始配置」→ 检查表单 → 保存。
- 期望：欢迎窗无标准关闭按钮出口；表单预填智谱全部键值（含 `_NAME` 显示键计入额外键）且显示名留空；保存后状态项出现、该模型带「（默认）」标注；env 内容与切换前等价（幂等写）。另跑一次「退出」出口：应用退出且应用配置目录无模型写入、settings.json 字节不变。出处：§2 F6、§2 F3。
- 清理：恢复备份；清除临时配置目录。

### S7 编辑生效中模型立即应用【人工】
- 前置：备份真实 settings.json 与应用配置 config.json；应用常驻，当前为智谱。
- 步骤：偏好 → 选中智谱 → 主模型改为新值 → 保存。
- 期望：settings.json 的 `ANTHROPIC_MODEL` 立即变为新值；收到切换通知；下次开菜单智谱仍置顶勾选（不出现「自定义配置」弹窗）。出处：§2 F4 出口表（2026-11-04 裁决）。
- 清理：退出应用 → 恢复两份备份。

### S8 删除守卫与默认补位【人工】
- 前置：备份应用配置 config.json；恰好两个模型，第二个为默认。
- 步骤：尝试只剩一个时删除（应置灰）→ 恢复两个 → 删除默认模型。
- 期望：仅剩一个时 － 置灰不可点；删除默认后列表首个自动带「（默认）」徽标。出处：§2 F4。
- 清理：退出应用 → 恢复 config.json 备份。

### S9 `_NAME` 同步规则三例【自动化（单元测试）】
- 前置：无。
- 步骤：Task 1 单元测试运行。
- 期望：派生值跟随更新；自定义标签保留；清空双删；`[1M]`/`[1m]` 大小写混合各一例。出处：§2 F5（2026-11-04 裁决）。
- 判据：测试套件全绿。

### S10 settings.json 语义四路径【自动化（单元测试）】
- 前置：临时目录。
- 步骤：运行 Task 3 单元测试（替换保留、创建、损坏、只读前缀键四路径）。
- 期望：替换保留语义、创建路径、损坏抛错且字节不变、只读前缀键。出处：§2 F2、§4（D5 env 替换语义）。
- 判据：测试套件全绿。

### S11 通知授权被拒降级【人工】
- 步骤：系统设置中拒绝应用通知授权（或首次弹授权时拒绝）→ 执行一次切换。
- 期望：切换本身成功、env 正确；无通知且无错误弹窗、不重复请求授权。出处：§2 F2（通知授权降级要点）。
- 清理：无需。

### S12 开机自启【人工】
- 前置：应用位于 /Applications。
- 步骤：偏好开「开机自启」→ 注销重登。
- 期望：登录后状态项自动出现；关闭开关后注销重登不出现；开发目录直接运行时若系统拒绝登记 → 提示失败且开关回拨。出处：§2 F7。
- 清理：按需关闭开关。

### S13 .app 交付【人工】
- 步骤：`bash scripts/make-app.sh` → `plutil -lint`、`codesign -dv` → 放入 /Applications → `open`。
- 期望：脚本 exit 0；lint 与签名检查通过；启动后菜单栏出现状态项、无 Dock 图标。出处：plan.md Task 9；design §5（交付物条目）。
- 清理：无需。

### S14 表单校验【人工，规则由单元测试覆盖】
- 步骤：偏好 ＋ 新建 → 依次输入空名/重名/缺必填。
- 期望：三类错误逐字段提示且不落库；全部通过后模型入列尾、不成为当前。出处：§2 F5、§2 F4。
- 清理：删除测试模型。

### S15 新会话最终效果【人工】
- 前置：紧接 S1 步骤执行——S1 期望核对完成后**暂不执行 S1 清理**（保持已切换到 DeepSeek 状态）。
- 步骤：终端新建 `claude` 会话 → 运行 `/model`（或发送一条消息观察响应方）。
- 期望：新会话实际使用 DeepSeek 模型（非智谱）。出处：§1 成功判断标准；§5 上游风险可观察信号。
- 清理：退出会话；随后一并执行 S1 清理（恢复备份）。

## 3. 通过判据

- 自动化场景：`swift test` 全绿，覆盖 S9/S10 对应断言。
- 人工场景：S1–S8、S11–S15 每条期望逐项核对通过；任一期望不符即失败并进入修复闭环（见 §6）。

## 4. 验证环境

- 单元测试：`swift test`（仓库根目录）；macOS 27、CLT Swift 6.4。
- 人工场景：`bash scripts/make-app.sh` 产物安装于 /Applications 或开发目录 `swift run`（涉及登录项的 S12 必须 /Applications）；真实用户目录。

## 5. 执行手段

- 资产化测试：Task 1–8 各任务单元测试（含 Task 5 ModelSwitcherTests）进 `swift test` 套件，回归常驻。
- 人工验证清单：S1–S8、S11–S15（已在场景标题标注【人工】）。

## 6. 内容要求落实

- **确定性固定策略：** S1/S2/S6 的 env 期望值以「与模型保存值完全一致/字节不变」表述，不依赖易变 UI 细节；文案逐字核对。
- **保真度声明：** 单元测试运行于临时目录，不等于真实环境；真实接口行为由 S1–S5 人工场景在真实 settings.json 上保真覆盖。
- **副作用隔离：** 一切触及真实 settings.json 或真实应用配置的场景（S1–S8、S15）执行前备份对应文件至临时目录、结束恢复；S6 的应用配置走临时目录。
- **顺序依赖：** S2 依赖 S1 的备份前置；S4/S5 依赖 S3 前置；S7 前需应用常驻（S1 后状态）；S15 紧接 S1 期望核对后、S1 清理前执行。
- **既有登记册查重：** 本仓库无既有验证登记册（新项目首次建册）。
- **失败证据采集：** settings.json 切换前后副本、通知与弹窗截图、`swift test` 完整输出、涉及的菜单状态截图。

**修复闭环轮次上限：3**（同一场景连续 3 轮修复仍失败 → 停止，向需求方呈报失败证据与建议）。
