## 0. 形态声明

产物形态：桌面 App（既有 macOS 菜单栏应用的视觉层迭代）。
章节裁剪推导：界面规格——适用（本需求全部为视觉产物）；数据字典——不设（本需求零新增持久化与外部格式，数据形态沿用已归档的 CC Model 设计，物理实现见既有 implementation 定义）。

## 1. 背景与目标

- 解决什么问题：当前界面全部使用系统默认样式——状态项是文本「⇄」前缀、三个窗口是默认灰面板、偏好窗口尺寸偏小导致字段拥挤、窗口出现在屏幕左上角。需求方反馈「太丑」「有点土」「大小不合理、选项显示得太挤」「位置不对」「遮挡/拥挤是严重问题」。
- 给谁用：需求方本人（单机个人工具的既有用户）。
- 成功判断标准：需求方打开偏好设置窗口后，尺寸与排版达到其确认的高保真稿密度；状态项显示独立设计的图形图标；三个窗口每次打开都居中于屏幕且呈深色主题——以上均为可观察行为。

## 2. 功能清单

### V1 菜单栏状态项图标

1. **定位：** 把文本「⇄」前缀替换为独立设计的图形图标，与模型名并列。
2. **触发与输入：** 应用启动即生效；供应商切换时模型名部分照旧更新。
3. **执行要点：**
   - 图形为系统符号库的「直线双向箭头」（终审视觉稿 D 方向，见冻结稿 mockups/exploration.html 的 icon-swap 卡）。
   - 图标为单色模板图，随菜单栏明暗自动适配。
   - 图标右侧仍显示当前模型显示名（截断规则沿用既有口径）。
   - 菜单、点击行为、通知等一切非视觉行为不变。
4. **出口表：** 单一出口——启动后状态项呈现「图形图标 + 模型名」。
5. **流程图：** 不配图——纯视觉替换，无分支。
6. **本次不做：** 见 §3 第 3 条。

### V2 深色主题

1. **定位：** 三个窗口（偏好设置、首跑、导入弹窗）统一呈现现代深邃的深色主题。
2. **触发与输入：** 应用启动即生效；无需任何用户操作。
3. **执行要点：**
   - 深色基调与层次关系按冻结稿 mockups/preferences.html：深色卡面、侧栏更深一档、细分隔线、主按钮蓝紫渐变、选中行高亮、「默认」徽标渐变胶囊、辅助文字弱化灰。
   - 深色为固定外观，不随系统明暗切换。
   - 表单可用性不降级：输入框、密文态 Token、错误提示在深色下均清晰可辨。
4. **出口表：** 单一出口——三窗口呈现统一深色主题。
5. **流程图：** 不配图。
6. **本次不做：** 见 §3 第 1、4 条。

### V3 窗口居中

1. **定位：** 全部窗口打开时居中于屏幕正中。
2. **触发与输入：** 每次任一窗口打开（偏好设置、首跑欢迎、首跑表单、导入弹窗）。
3. **执行要点：**
   - 每次打开都以当前屏幕正中为锚定位，不沿用系统默认的左上级联位置。
   - 多显示器环境以主屏为居中锚。
   - 导入弹窗与偏好窗口同规则。
4. **出口表：** 单一出口——窗口居中出现。
5. **流程图：** 不配图。
6. **本次不做：** 见 §3 第 5 条。

### V4 偏好窗口尺寸与排版

1. **定位：** 解决「太小、太挤」——加大窗口、松开排版、档位映射改横排。
2. **触发与输入：** 打开偏好设置窗口（链路见既有功能 F4）。
3. **执行要点：**
   - 默认尺寸 720×480，最小 660×430，允许拖拽调整。
   - 侧栏宽约 200pt；表单区内边距约 20pt、行间距约 14pt。
   - 四档映射（Fable/Opus/Sonnet/Haiku）横排四列，列宽均分。
   - Token 行保留密文态与明/密文切换。
   - 「保存」为渐变主按钮；「设为默认」勾选框在表单底部左侧。
4. **出口表：** 单一出口——窗口按新尺寸与排版呈现，保存行为不变。
5. **流程图：** 不配图。
6. **本次不做：** 见 §3 第 2 条。

### V5 首跑窗默认行收敛

1. **定位：** 首跑表单隐藏「设为默认」行——首跑单模型必然成为默认，界面不再给出无差异的勾选。
2. **触发与输入：** 首跑表单渲染时。
3. **执行要点：**
   - 首跑窗的表单不出现「设为默认」勾选行。
   - 偏好窗口表单保留该行（既有语义不变）。
   - 保存后首个模型仍自动成为默认（既有行为不变）。
4. **出口表：** 单一出口——首跑表单无默认勾选行，保存行为与先前一致。
5. **流程图：** 不配图。
6. **本次不做：** 见 §3 第 2 条。

## 3. 明确不做

1. 不改任何功能行为语义——因为本需求定位为纯视觉层迭代，切换、增删改、导入、通知等行为已在既有设计确认并交付，本需求只动「看起来是什么样」。
2. 不做浅色主题与系统明暗跟随——因为需求方选定深色方向且本应用为个人工具，双主题的成本（两套配色核对）不产生对应收益。
3. 不做应用图标（Dock/Finder 图标）设计——因为应用常驻菜单栏无 Dock 存在感（accessory 应用），Dock 图标几乎不可见，收益趋近于零。
4. 不做过场动画、自定义字体、窗口透明/模糊效果——因为视觉稿确认稿不含这些元素，加入即偏离已确认的视觉方向。
5. 不做多显示器逐屏记忆位置——因为单用户单屏为主，居中主屏已满足需求，逐屏记忆是新功能。

## 4. 关键决策记录

| 决策 | 一句话结论 | 拍板状态 | 影响功能项 |
|------|-----------|---------|-----------|
| D1 图标方向 | 系统符号库直线双向箭头 | 已裁决（2026-11-06，视觉稿点选 icon-swap） | V1 |
| D2 主题方向 | 现代深邃，固定深色 | 已裁决（2026-11-06，视觉稿点选 color-dark） | V2 |
| D3 窗口位置 | 全窗口打开居中 | 已裁决（2026-11-06，需求方明示） | V3 |
| D4 面板尺寸密度 | 默认 720×480、横排档位 | 已裁决（2026-11-06，高保真稿确认） | V4 |
| D5 首跑默认行 | 首跑窗隐藏，偏好窗保留 | 已裁决（2026-11-06，顺带收敛终审遗留项） | V5 |

**D1 图标方向**
1. 候选：系统环形交换符号；系统直线双向箭头；供应商首字渐变徽标；自绘圆环线条徽标。
2. 选择：系统直线双向箭头。
3. 依据：视觉稿并排对比由需求方点选（decisions.md 首条）；系统符号原生自适应明暗菜单栏，零违和风险。
4. 代价：放弃徽标方案的「供应商一眼可辨」信息量——该信息已由图标旁的模型名承担。成本量级：可忽略。

**D2 主题方向**
1. 候选：维持系统默认；现代深邃固定深色；清爽浅色。
2. 选择：现代深邃固定深色。
3. 依据：视觉稿并排对比由需求方点选；「现在的有点土」直接指向默认灰。
4. 代价：浅色系统下窗口仍为深色（刻意选择，与菜单栏工具的暗色气质一致）；两套配色适配成本为零是本选择的直接收益。成本量级：小。

**D3 窗口位置**
1. 候选：维持系统默认级联位置；每次打开居中；记住上次位置。
2. 选择：每次打开居中。
3. 依据：需求方明示「面板打开应该在屏幕的正中央，现在位置不对」。
4. 代价：放弃「记住位置」的个性化——个人工具单屏场景收益不成立。成本量级：可忽略。

**D4 面板尺寸密度**
1. 候选：维持现尺寸仅松行距；720×480 + 横排档位；更大尺寸（如 820×520）。
2. 选择：720×480 + 横排四列档位，最小 660×430。
3. 依据：高保真稿按真实比例呈现，需求方「均接受」；现窗口的实际痛点是「字段挤」而非「窗口不够大」。
4. 代价：小屏（如 1280×800 逻辑分辨率）下 720×480 仍可完整容纳，无风险；横排档位列宽均分在长模型名下可能截断省略——示意级可调。成本量级：小。

**D5 首跑默认行**
1. 候选：维持现状（勾选无差异）；首跑窗隐藏该行；保存时尊重勾选状态。
2. 选择：首跑窗隐藏该行。
3. 依据：终审遗留项建议 + 表单复用参数化是最小改动路径；「勾选无差异」的 UI 是承诺与事实不一致。
4. 代价：偏好窗与首跑窗的表单出现一行差异（参数化承担）。成本量级：可忽略。

**留给构建者的部分**

- 图标在状态项按钮上的精确渲染方式（符号图与文字的间距、基线对齐），边界：最终观感须与冻结稿一致；为什么交构建者：渲染细节是平台适配层。
- 深色在各系统控件（文本框、开关、弹窗按钮）上的自动适配确认——控件原生深色已由固定外观达成，逐控件配色微调（如输入框底色深一度）留给构建者，边界：不偏离冻结稿的整体观感。
- 居中的实现机制（窗口基座统一处理或逐窗口设置），边界：三个窗口 + 弹窗全部居中、多屏取主屏；为什么交构建者：机制选择不影响行为。

## 5. 关键约束与可行性风险

- 行为零变更红线：139 条既有测试必须保持全绿；本需求只动视觉层。
- 图标必须使用系统符号库资源——不引入图片资产与第三方图标库（零依赖红线沿用）。
- 深色固定外观对本机浅色系统的用户是显性变化——需求方已选定，属已接受变化而非风险。
- 环境注意（沿用既有事实）：构建测试的宏插件冷启动失败为已知 flake，处置序列照旧。
- 成本量级：单人约 0.5–1 个工作日（视觉层改动 + 人工验证场景核对）。
